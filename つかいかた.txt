============================================================================================
DeployKit で新規プロジェクトにセットアップする場合
============================================================================================
１．DeployKit フォルダを、Unity プロジェクトがあるフォルダに置きます
２．DeployKit\Setup.bat を実行します
　　→ Unity プロジェクトを自動検出し、必要なファイルを配置します
　　→ 既存ファイルがある場合は上書き確認が出ます
３．以降は下記の「Unityエディタを起動せずにビルドを実行するまで」に進みます

============================================================================================
Unityエディタを起動せずにビルドを実行するまで
============================================================================================
１．Assets/Editor/ 以下に AutoBuildSystem.cs と BuildConfig.json.template が
　　あることを確認します（BuildConfig.json は初回起動時に自動生成されます）
２．Tool\path.ini.template をコピーして Tool\path.ini を作成し、以下を設定します
　　1行目: 制作に使用しているバージョンの Unity.exe のフルパス
　　2行目(省略可): Unityプロジェクトフォルダのフルパス
　　※省略した場合、リポジトリ直下から自動検出されます
　　　（Assets と ProjectSettings を含むフォルダを探します）
３．Unityを起動し、プロジェクトを選択してエディタを開きます
４．エディタが開いたら上部メニューバーの Tools > Auto Build System を選択します
５．保存したいフォルダを絶対パスで記述し、設定保存を押します
６．ビルド実行を押してリリースビルドおよびデバッグビルドの両方が
　　zipファイルで出力されていれば成功です
７．以後、Tool\Deploy.bat を実行するだけで、ゲームパッケージが指定したフォルダにビルドされます
※ビルドセッティング（シーンの登録等）は各自でやってください。

============================================================================================
バージョン管理について
============================================================================================
■ ビルドのバージョン
　Edit > Project Settings > Player > Version で手動管理します。
　マイルストーンやリリースごとに上げてください（例: 0.1.0 → 0.2.0 → 1.0.0）

■ ビルド出力のファイル名
　プロジェクト名_ビルド区分_vバージョン.zip
　例：TestProject_Release_v1.0.0.zip、TestProject_Debug_v1.0.0.zip

■ GitHub Actions（CI）のビルド
　CIでビルドした場合、アーティファクト名にビルド番号が自動付加されます。
　例：Build-v1.0.0+build42

============================================================================================
以下、gitにプロジェクトのルートフォルダをリポジトリとして追跡させている場合
============================================================================================

■ Git LFS の初期設定（初回のみ）
　Git for Windows をインストールすると Git LFS も同梱されています。
　プロジェクトフォルダで以下のコマンドを実行してください：
　　git lfs install

■ リポジトリのクローン
　以下のコマンドでリポジトリをクローンしてください：
　　git clone https://github.com/ユーザー名/リポジトリ名.git

■ Git認証の設定（Git Credential Manager）
　Git for Windows に同梱の Git Credential Manager を使用します。
　特別な設定は不要で、初回の fetch/push 時に認証ダイアログが表示されます。
　ダイアログでGitHubアカウントにログインすれば、以後は自動的に認証されます。

　※Credential Manager が動作しない場合は以下のコマンドを実行してください：
　　git config --global credential.helper manager

■ Fetch.bat の実行
　８．Tool\Fetch.bat を実行して、エラーがないか確認してください
　９．エラーがなければ、次回以降は Tool\FetchAndDeploy.bat を実行します
　　　FetchAndDeploy.bat は gitからソースを最新に更新し、ビルドして指定フォルダに出力します

■ giturl.ini について（廃止）
　以前のバージョンで使用していた giturl.ini は廃止されました。
　トークンを平文で保存するのはセキュリティ上危険なため、
　Git Credential Manager による安全な認証に移行しました。
　giturl.ini が残っている場合は削除してください。

ビルドを自動化するための作業手順
============================================================================================
１．Windowsタスクスケジューラに Tool\FetchAndDeploy.bat を登録します
　　（例：毎日AM3:00に実行するように設定）
２．おわり。あとは勝手にデプロイしてくれます。

Googleドライブへの自動アップロード
============================================================================================
１．Googleドライブ（デスクトップアプリ版）をインストール
２．自動同期フォルダを設定
３．Unityエディタの Tools > Auto Build System で
　　Googleドライブフォルダパスをそのフォルダに変更
４．設定保存 → ビルド実行
　　ビルド成果物がGoogleドライブに自動同期されます

============================================================================================
GitHub Actions（CI/CD）について
============================================================================================
GitHub にプッシュした際に自動テスト・ビルドを走らせたい場合は、
.github/workflows/build.yml が用意されています。
リポジトリの Settings > Secrets and variables > Actions に以下を設定：
　・UNITY_LICENSE — Unity ライセンスファイル (.ulf) の内容
　・UNITY_EMAIL — Unity アカウントメール
　・UNITY_PASSWORD — Unity アカウントパスワード
プッシュ時に EditMode テストが実行され、成功後に Windows ビルドが行われます。
ビルド成果物はアーティファクトとしてダウンロード可能です（14日間保持）。

■ 自動リリース（main ブランチのみ）
　main ブランチにプッシュされると、CI が自動で GitHub Release を作成します。
　ビルド成果物が zip で添付され、チームメンバーがダウンロードできます。

============================================================================================
Git Flow ブランチ運用（チーム開発）
============================================================================================

■ ブランチの種類
　・main     — リリース用。常に動作する状態を保つ。直接プッシュは原則禁止。
　・develop  — 開発用の統合ブランチ。feature の成果をここにマージする。
　・feature/ — 各自の作業ブランチ。develop から分岐し、develop に PR でマージ。
　　例: feature/add-new-enemy, feature/fix-ui-layout

■ バッチファイル一覧（Tool\ フォルダ内）
　・Tool\NewFeature.bat   — 新しいフィーチャーブランチを作成する
　・Tool\SwitchBranch.bat — ブランチを切り替える（番号選択）
　・Tool\Fetch.bat        — リモートの最新変更を取り込む（現在のブランチに対応）
　・Tool\PushBranch.bat   — 現在のブランチをリモートにプッシュする
　・Tool\BranchStatus.bat — 現在のブランチの状態を確認する（読み取り専用）
　・Tool\Deploy.bat       — ビルドを実行する（従来通り）
　・Tool\FetchAndDeploy.bat — Fetch + ビルドを一括実行（従来通り）

■ 日常の作業フロー
　１．新しい作業を始めるとき
　　　Tool\NewFeature.bat をダブルクリック → フィーチャー名を入力
　　　例: add-title-screen と入力 → feature/add-title-screen ブランチが作成される

　２．毎日の作業
　　　・Unity で作業する
　　　・Tool\Fetch.bat をダブルクリック → リモートの最新を取り込む
　　　  （変更は自動コミットされてからリベースされます）

　３．作業を共有したいとき
　　　Tool\PushBranch.bat をダブルクリック → リモートにプッシュ
　　　→ feature ブランチの場合は PR 作成 URL が表示される

　４．作業が完了したとき
　　　・GitHub で develop 宛のプルリクエスト（PR）を作成
　　　・チームメンバーにレビューしてもらい、マージ

　５．リリースするとき
　　　・GitHub で develop → main の PR を作成
　　　・マージすると CI が自動でビルド＋GitHub Release を作成

■ Unity Editor からの操作（Git Flow エディタ拡張）
　バッチファイルと同等の Git Flow 操作を Unity Editor 内で行えます。
　エディタから離れずに操作できるため、非エンジニアにも便利です。

　【開き方】
　　Unity エディタ上部メニュー → Tools → Git Flow

　【機能一覧】
　　・ステータス表示 — 現在のブランチ、コミット、ahead/behind、変更ファイル数
　　・最新を取得 (Fetch) — Fetch.bat と同等（自動コミット→fetch→rebase）
　　・プッシュ (Push) — PushBranch.bat と同等（main 警告、PR URL 表示あり）
　　・新規フィーチャー作成 — NewFeature.bat と同等（名前を入力して作成）
　　・ブランチ切り替え — SwitchBranch.bat と同等（ドロップダウンで選択）
　　・ログエリア — 操作結果がウィンドウ下部に表示されます

　【注意事項】
　　・バッチファイルは引き続き使用できます（Editor 外・CI 等で利用）
　　・Git 操作後はプロジェクトが自動的に再読み込みされます

■ よくある質問

　Q. 今どのブランチにいるか分からない
　A. Tools → Git Flow を開くと、ウィンドウ上部に現在のブランチと状態が表示されます。
　   バッチファイルの場合は Tool\BranchStatus.bat をダブルクリックしてください。

　Q. 他の人のブランチに切り替えたい
　A. Tools → Git Flow の「切り替え先」ドロップダウンから選んで「ブランチ切り替え」を押します。
　   リモートにしかないブランチも自動的にローカルに作成されます。
　   バッチファイルの場合は Tool\SwitchBranch.bat をダブルクリックしてください。

　Q. Fetch でコンフリクトが出た
　A. 同じファイルを複数人が編集した場合に発生します。
　   プログラマーに相談して解決してください。
　   解決後は以下のコマンドを実行: git rebase --continue

　Q. 間違えて main ブランチで作業してしまった
　A. Tools → Git Flow の「ブランチ切り替え」で正しいブランチに切り替えてください。
　   変更は自動コミットされるので失われません。

　Q. Push で「main にプッシュしようとしています」と警告された
　A. 通常は feature ブランチで作業してください。
　   キャンセルして「新規フィーチャー作成」で新しいブランチを作成してください。

　Q. PR（プルリクエスト）って何？
　A. ブランチの変更を別のブランチに取り込む依頼のことです。
　   GitHub 上でコードの差分を確認でき、レビューしてからマージできます。
　   Push 後にログエリアに表示される URL をブラウザで開くと作成画面が開きます。
