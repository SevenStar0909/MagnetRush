# プレイヤー実装：空中アニメーション

> 共通ルール（アーキテクチャ分担・禁止事項・プルリクエスト分割順序等）は [プレイヤー実装ルール_共通.md](プレイヤー実装ルール_共通.md) を参照。

ジャンプ機能（[プレイヤー実装_ジャンプ.md](プレイヤー実装_ジャンプ.md)）の完了後に着手する想定。

---

## 1. 機能要件

- プレイヤーが**接地していない間**は空中用モーション（上昇 / 下降 / 着地）が再生される
- ジャンプ経由でも、段差落下経由でも、**接地フラグが false なら空中扱い**
- 接地復帰時は短い着地モーションを経由してから通常状態に戻る

---

## 2. 設計ルール

**Controller / State の新規追加はしない**（State は既にジャンプタスクで `FallPlayerState` が作成済みの前提）。空中アニメは「`FallPlayerState` + 垂直速度の Float」から派生する**演出**であって、能動的な行動ではない。

- **Animator 側で既存 `IsGrounded` Bool と新規追加する `VerticalSpeed` Float を見て、サブステートマシンで上昇/下降/着地を切り替える**
- **垂直速度は新規 Animator パラメータ `VerticalSpeed` (Float) として、既存 `PlayerAnimator` から送出する**。既存 `Entity.velocity.y` をそのまま流せばよい
- 新規パラメータを追加したら **既存 `PlayerAnimator.ValidateAnimatorParameters()` の検証配列にも必ず追加する**（漏れを検出するため）
- 既存 `FallPlayerState`（ジャンプタスクで作成済み）にいる間は常に空中モーションが流れる。ジャンプ経由でも段差落下経由でも、`FallPlayerState` に入っていれば空中扱いで一元化される
- エイム中の落下・着地でもエイム姿勢が崩れないよう、Animator のレイヤー構成を考えること

### 段差落下経由の `FallPlayerState` 遷移を有効化する（本タスクで追加）

ジャンプタスクではジャンプ起点の `FallPlayerState` 遷移しか実装されていない。本タスクで以下の遷移チェックを `Player.Update()` に追加する:

- 現在 State が `Move` / `Idle` / `Aim` のいずれかで、かつ既存 `Entity.IsGrounded == false` になった場合、`FallPlayerState` へ遷移する
- 既存の State 切替は壊さない（Aim 中に空中になったら `FallPlayerState` に飛ぶ vs エイム維持で空中になる、はプランナー確認項目）

---

## 3. 作成・改修するスクリプト

Controller / State の新規スクリプトは作らない。既存スクリプトと Animator Controller への追加のみ。

### 新規作成

#### 空中モーション Clip 群

配置: `Animations/Player/Clips/`

- 上昇 / 下降 / 着地 の3つ
- BlendTree 用に統合してもよい

### 改修

#### `PlayerAnimator.cs`

配置: `Scripts/Core/Player/`

新規メンバ:

- `private string m_verticalSpeedName = "VerticalSpeed"` — Animator パラメータ名の文字列定数
- `private int m_hVerticalSpeed` — StringToHash で変換した数値ハッシュ

既存メソッドへの追記:

- 既存 `Start()` で `Animator.StringToHash` を使い `m_hVerticalSpeed` を初期化する
- 既存 `LateUpdate()` で 既存 `Entity.velocity.y` を Animator の `VerticalSpeed` Float パラメータに毎フレーム送出する（既存 `MoveSpeed` 送出と同じブロック内に追記）
- 既存 `ValidateAnimatorParameters()` の expected 配列に `VerticalSpeed` (Float) のエントリを追加し、Animator Controller との不整合を検知できるようにする

#### `PlayerAnimator.controller`

配置: `Animations/Player/`

新規 Animator パラメータ:

- `VerticalSpeed` (Float)

新規 Sub-State Machine `Airborne`:

- 内部 State: `JumpAnim` / `FallAnim` / `LandAnim`
- 命名: `*Anim` サフィックスは既存ボス Animator と統一

遷移条件:

- `Locomotion` / `Aim` → `Airborne`: `IsGrounded == false`
- `Airborne` 内 `JumpAnim` ↔ `FallAnim`: `VerticalSpeed > 0` で上昇、`<= 0` で下降
- `Airborne` → `Locomotion` / `Aim`: `IsGrounded == true` （`LandAnim` を 0.1〜0.2 秒挟む）

---

> 空中アニメをエイム時にも被せたい場合は、Animator のレイヤー構成（Override Layer）を組む必要がある。詳細はプランナー確認待ち項目参照。

---

## 4. 受け入れ基準

- [ ] ジャンプ直後 → 上昇モーション、頂点超え → 下降モーション、接地 → 着地経由で通常モーションに戻る
- [ ] 段差落下（ジャンプ未経由）でも下降モーションに入る
- [ ] エイム中の落下・着地でもエイム姿勢が維持される（Layer 構成で実現）
- [ ] Console に `[PlayerAnimator]` のパラメータ未定義 LogError が出ない

---

## 5. プランナー確認待ち

実装着手前にプランナーに確認:

- エイム中の空中挙動（エイム姿勢を保つか、空中専用モーションに切り替えるか）
- 着地モーションの長さ（ガクッと止まる感じ vs スムーズに繋ぐ感じ）
